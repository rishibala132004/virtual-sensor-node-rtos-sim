# Virtual Sensor Node Simulation

This project implements a Virtual Sensor Node Simulation in C. It models an embedded system with multiple tasks scheduled by a simulated Real-Time Operating System (RTOS). It features realistic sensor simulation with noise and drift, exponential moving average (EMA) filtering, and inter-process communication (IPC) via a ring buffer. The project also provides Python scripts for visualizing the generated simulation data.

## Features

*   **RTOS Task Scheduler:** A simple, time-triggered scheduler that manages multiple tasks with defined periods, execution times, and priorities.
*   **Sensor Simulation:**
    *   **Temperature Sensor:** Simulates a temperature sensor with a baseline value, slow drift, and random noise.
    *   **Accelerometer:** Simulates an accelerometer experiencing a sinusoidal movement pattern (±2g) with added noise.
*   **Data Processing:**
    *   **EMA Filter:** A background task applies an Exponential Moving Average (EMA) filter to the raw temperature data to smooth out noise.
*   **Inter-Process Communication (IPC):**
    *   Tasks use a shared ring buffer to communicate data (temperature, filtered temperature, acceleration) asynchronously.
    *   A simulated UART communication task reads from this buffer and "transmits" the data.
*   **Timing and Energy Analysis:**
    *   The simulation tracks and outputs comprehensive statistics, including:
        *   Simulated elapsed time.
        *   Estimated total energy consumption (mJ) and average power (mW) based on task execution times and power profiles.
        *   CPU utilization (active vs. idle time).
        *   Per-task timing metrics: average execution time, response time, jitter (standard deviation of response time), and deadline miss rates based on simulated Worst-Case Execution Time (WCET).
        *   Ring buffer utilization and drop counts.
*   **Data Visualization:** A Python script is provided to parse the simulation log output and generate detailed plots using Matplotlib, illustrating raw vs. filtered data, sensor motion, and the timing of transmitted packets.

## Directory Structure

*   **`src/`**: Contains the main C source code for the simulation.
    *   `firmware.c`: The core simulation logic, including the scheduler, tasks, and sensor models.
*   **`scripts/`**: Contains Python scripts for data analysis and visualization.
    *   `plotschedule.py`: A script that parses a log file generated by the C program and creates a 3-panel plot (`sensor_plots.png`).
*   **`logs/`**: Directory intended for storing the output logs of the simulation runs. (e.g., `run1.log`, `run_upgraded.log`).

## Dependencies

To run this project, you will need:

*   **A C Compiler:** GCC or Clang (to compile the C simulation).
*   **Python 3:** (to run the visualization scripts).
*   **Python Libraries:**
    *   `matplotlib`
    *   `numpy`

    You can install the Python dependencies using pip:
    ```bash
    pip install matplotlib numpy
    ```

## Usage Instructions

Follow these steps to build, run, and visualize the simulation:

### 1. Compile the Simulation

Navigate to the project root directory and compile `src/firmware.c` using your C compiler. Here is an example using GCC:

```bash
gcc src/firmware.c -o firmware -lm
```
*(Note: the `-lm` flag is required to link the math library for the sine function used in the accelerometer simulation).*

### 2. Run the Simulation and Save the Log

Execute the compiled program and redirect its output (stdout) to a log file in the `logs` directory. The Python visualization script expects the log file to be located at `../logs/run_upgraded.log` relative to the `scripts` directory.

```bash
./firmware > logs/run_upgraded.log
```
*(This will run the simulation for its configured duration, which is 10 seconds by default, and save all output to the log file).*

### 3. Visualize the Results

Navigate to the `scripts` directory and run the `plotschedule.py` script to generate the plots.

```bash
cd scripts
python3 plotschedule.py
```

This script will read the data from `../logs/run_upgraded.log`, parse the timestamps and sensor values, and generate a 3-panel plot saved as `sensor_plots.png` in the `scripts` directory. It will also display the plot window if your environment supports it.

The generated plot (`sensor_plots.png`) will include:
1.  **Temperature:** A comparison of the raw temperature sensor readings (red) versus the smoothed EMA filtered readings (blue).
2.  **Accelerometer:** A plot of the simulated sinusoidal acceleration data with noise.
3.  **Ring Buffer IPC:** A scatter plot illustrating when UART TX packets were sent, showing the transmitted acceleration and temperature values over time.
